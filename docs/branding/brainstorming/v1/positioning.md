# Positioning

## One line

Gongsho turns a request into running deployments.

## Story

Deployments are long-lived workloads; pods are their runtime instances,
so the leaf survives scale-out without a rename. The brand says the
same thing in human terms: put the fragile thing (your request) inside
something small, round, and safe, and let a boring harness carry it to
production.

Three brand pillars follow the build order in the roadmap:

1. **Templates** (done) — `goa-api` and `react-ui`, the proven seeds.
2. **Console** (next) — teams, projects, and deployments in one surface.
3. **Apps** (after) — what others grow from the console.

## Name

**Gongsho**, capitalized in prose, lowercase `gongsho` in the wordmark,
code, paths, and CLI output. Pronounced GONG-sho. Never camelCase,
never all-caps (the all-caps shout contradicts the boring promise).

## Taglines

- Primary (product truth, already on the docs site): **Design, scaffold,
  and deploy apps through agents and a boring shell harness.**
- Short lockup (brand feeling): **Friendly pods. Boring promises.**
- Deployment footer (co-branding): **Built in a gongsho pod.**

Use the primary where you explain, the short one where you sign.

## Audience

Developers and agents building `team / project / deployment` apps from
templates. They trust file copies, health checks, and READMEs over
magic. Speak to them concretely: name the files, the ports, the checks.

## Personality

Playful about pods, boring about promises. Round shapes, multiplying
dots, and warm paper carry the play. Claims about reliability stay
plain, synchronous, and checkable — the way the harness already behaves.
