# Phase 1 plan — templates, tools, demo

Status: draft for review, 2026-11-11. Companion to `../roadmap.md`
(overall phases; canonical home of deferred decisions) and
`../agent-workflow-usecase-1.md` (triage plus edit flow).

Scope: this plan builds templates, tools, and the combined demo only. It does
not build planner/worker agents, the console, or packaging, per your standing
holds. Recommendations from discussion are baked in as assumed defaults
(collected near the end for review); flag any to change.

## Goal

Phase 1 delivers `goa-api` and `react-ui` templates plus a `.sh` harness such
that a fresh-prompt Muse session can scaffold, build, deploy, verify, and tear
down deployments with no tribal knowledge — proven by a combined demo project
running two APIs and one UI off one localhost Caddy.

## Detail specs

Full concrete specifications live beside this file: `repository-layout.md`
(annotated tree plus commit rules), `descriptors.md` (both YAML schemas with
examples), `ids-and-routing.md` (rules, derivations, URLs), `proxy.md` (main

`migrations.md` (placement plus backup discipline), `spec-handoff.md`
(snapshots plus freshness), `demo.md` (combined demo composition).

## Key decisions

- API stack is Goa: design DSL in, HTTP/gRPC/JSON-RPC servers plus OpenAPI out
  ([Goa](https://goa.design/), [Goa docs](https://goa.design/docs/)); v1 wires
  HTTP/JSON only (assumed). OpenAPI-first alternatives oapi-codegen
  ([repo](https://github.com/oapi-codegen/oapi-codegen)) and ogen
  ([repo](https://github.com/ogen-go/ogen)) were evaluated and rejected as
  HTTP-only: gRPC/JSON-RPC would need a second contract later.
- UI stack is React as a Vite static SPA: tied-best SPA accuracy in
  [DesignBench](https://arxiv.org/html/2506.06251v1), simplest stacks cheapest
  in the [12-framework agentic test](https://www.coodryx.com/blog/ai-coding-benchmark-javascript-frameworks),
  dominant usage share ([Stack Overflow 2025](https://survey.stackoverflow.co/2025/technology)).
  No BFF: serving is proxy config. `nextjs-ui` stays a future template.
- Subpath serving via the Vite `base` option including its `--base` build flag
  for dev-bundle rebuilds ([Vite build](https://vite.dev/guide/build)).
- TS client generated by Hey API inside the UI build from pinned spec snapshots
  ([get-started](https://heyapi.dev/openapi-ts/get-started.html),
  [@hey-api/openapi-ts@0.99.0](https://registry.npmjs.org/@hey-api%2Fopenapi-ts/latest));
  exact-pin the 0.x line. openapi-typescript@7.13.0
  ([registry](https://registry.npmjs.org/openapi-typescript/latest)) is the
  documented fallback. TanStack hooks (noted on the same Hey API pages) stay
  a later plugin toggle.
- Proxy is Caddy on one localhost port (`:8080`, assumed): prefix-strip
  subfolder proxying ([reverse_proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy)),
  glob imports ([import](https://caddyserver.com/docs/caddyfile/directives/import)),
  graceful reload ([command line](https://caddyserver.com/docs/command-line)),
  lightest idle RAM in the inspected benchmark
  ([benchmark](https://deployn.de/en/blog/reverse-proxy-benchmark-2026/)).
  nginx ([guide](https://docs.nginx.com/nginx/admin-guide/web-server/reverse-proxy/))
  and Traefik ([rules](https://doc.traefik.io/traefik/reference/routing-configuration/http/routing/rules-and-priority/))
  rejected as heavier per-route config for a static local file.
- UI stanza follows Caddy's documented SPA pattern verbatim
  ([patterns](https://caddyserver.com/docs/caddyfile/patterns)): root
  ([root](https://caddyserver.com/docs/caddyfile/directives/root)) plus
  try_files fallback ([try_files](https://caddyserver.com/docs/caddyfile/directives/try_files))
  plus file server ([file_server](https://caddyserver.com/docs/caddyfile/directives/file_server))
  plus per-path cache headers ([header](https://caddyserver.com/docs/caddyfile/directives/header)).
- DB is SQLite per roadmap: single-file database
  ([About SQLite](https://www.sqlite.org/about.html)), so backup-before-migrate
  is a file copy; `db.path` stays a mount-ready path for later persistent
  volumes ([volumes](https://kubernetes.io/docs/concepts/storage/volumes/)).
- Migrations via golang-migrate: versioned up/down pairs, SQLite drivers,
  embeddable sources ([repo](https://github.com/golang-migrate/migrate));
  goose ([repo](https://github.com/pressly/goose)) is second for its Go-code
  migrations if data transforms dominate later.
- API e2e runner is `go test` plus testify (`require` fatals, `assert` flow
  checks; [README](https://raw.githubusercontent.com/stretchr/testify/master/README.md));
  stdlib [`httptest`](https://pkg.go.dev/net/http/httptest) covers in-process
  handler tests. UI e2e runner is Playwright Test across Chromium/Firefox/WebKit
  ([Playwright](https://playwright.dev/)), 576M vs Cypress 28M monthly downloads
  ([npm](https://api.npmjs.org/downloads/point/last-month/playwright,cypress)).
- Go per your Goa choice; Node present for UI builds (Hey API engines field,
  same registry page); YAML descriptors per your choice; Muse CLI as builder
  per your choice; Go per-template with no registry — all resolution derives
  from IDs, pins, and the filesystem.

## Repository layout (all new)

- Docs: `../roadmap.md`, `../agent-workflow-usecase-1.md`, plus this folder:
  `phase-plan.md` (this file), `repository-layout.md`, `descriptors.md`,
  `ids-and-routing.md`, `proxy.md`, `template-goa-api.md`,
  `template-react-ui.md`, `tools.md`, `supervision-and-runtime.md`,
  `e2e-standard.md`, `migrations.md`, `spec-handoff.md`, `demo.md`
- `templates/<name>/`
  - `.gongsho-tpl.yaml` — manifest: name, version, vars, owned list
  - `config/` — template-owned material: `caddy/stanza`, defaults, health spec
  - `app/` — scaffold source copied into deployments (only part Muse edits downstream)
  - `README.md` — written so Muse scaffolds, runs, and wires one unaided
- `apps/<team>/<project>/<deployment>/` — scaffolded source, flat once
  scaffolded (assumed): code, app config (Muse-editable, assumed),
  `.gongsho-deployment.yaml` pin (harness-owned), `migrations/` (APIs),
  `spec/` (UI snapshots), `e2e/` specs
- `bin/<team>/<project>/<deployment>/` — gitignored build output: API binary,
  UI bundle (what Caddy serves)
- `proxy/`
  - `Caddyfile` — localhost site plus `import deployments/*` and `import dev.d/*`
  - `deployments/` — stable stanzas, one file per deployment, committed in v1
    (assumed)
  - `dev.d/` — ephemeral `/dev/<session>/` stanzas, gitignored
  - `sockets/` — runtime unix sockets plus pidfiles, gitignored
- `run/` — per-session scratch (dev DBs, dev bundles), gitignored (assumed location)
- `tools/` — one `.sh` verb per file (assumed) plus `lib.sh` (ID validation and
  parsing, path derivation, Caddy reload, logging); every verb has `--help`,
  explicit args, and machine-readable exit codes plus concise stdout

## Template contracts

- `goa-api` (Goa per your choice)
  - Scaffold: `design/` package (example service plus method), service
    implementation skeleton, `migrations/` with the constants-first migration,
    `e2e/` with one HTTP flow test, app config, README
  - Manifest vars: `["id"]`; owned: `["proxy-stanza"]`
  - Guarantees: `gen/openapi.json` exists after build (normalized from wherever
    Goa emits it); serves its OpenAPI at a stable route; listens on its unix
    socket (acceptance criterion, verify at implementation); health endpoint
    per the template health spec
  - Transports HTTP/JSON only in v1 (assumed); gRPC/JSON-RPC unwired
- `react-ui` (React per evidence above)
  - Scaffold: Vite SPA skeleton with parameterized base, Hey API client
    generation wired into build from `spec/`, `e2e/` with one browser flow,
    app config, README
  - Manifest vars: `["id"]`; owned: `["proxy-stanza"]`
  - Guarantees: static bundle output; hashed assets under a predictable dir
    for the long-cache matcher (assumed); same-origin API calls only, so no
    CORS configuration exists
- Template versions are per-template two-part (`major.minor`): major means
  existing apps must change to match, minor is everything else. Apps pin exact.

## Deployment configuration

- `.gongsho-tpl.yaml` (in each template):
  `name`, `version` (quoted), `vars` (v1: `["id"]`), `owned` (v1:
  `["proxy-stanza"]`).
- `.gongsho-deployment.yaml` (in each deployment, harness-owned):
  `id` (`acme_shop_api-1`), `path` (`acme/shop/api-1`), `template`,
  `templateVersion` (quoted), `vars` (empty map in v1, kept for forward
  compat — assumed), `db` (APIs only: `type: SQLite`, repo-root-relative
  `path`), `created` (quoted timestamp). Scaffold validates id/path agreement.
- ID rules: segments allow lowercase, digits, hyphens only, never underscores,
  so the underscore join splits unambiguously; no team named `dev` (reserves
  the `/dev/` route prefix). Validation lives in `lib.sh`; no registry.
- Main `Caddyfile`: one localhost site containing only the two import lines.
- API stanza (rendered from `templates/goa-api/config/caddy/stanza`):
  `handle_path` matching the deployment path and stripping the prefix
  (assumed), `reverse_proxy` to the deployment socket with an explicit
  constant `Host localhost` (assumed; required for unix upstreams per the
  reverse_proxy docs linked above).
- UI stanza (rendered from `templates/react-ui/config/caddy/stanza`): root at
  the `bin/` bundle dir, `try_files` fallback to the entry file, `file_server`,
  no-cache entry header plus immutable hashed-asset headers (assumed split).
- Dev stanzas reuse the same shapes under `/dev/<session>/` with dev sockets
  and scratch roots. Caddy logging stays default in v1 (assumed).
- Filenames: proxy files and sockets use the underscore ID verbatim
  (`acme_shop_api-1`, `acme_shop_api-1.sock`); dev files prefix the session
  (`a3f9-acme_shop_api-1`, `acme_shop_api-1.dev-a3f9.sock`). Writes go
  temp-then-rename so concurrent reloads never read partial files.

## Tools and flows

- Project lane (human now, agents later): create, build, deploy, check, e2e,
  refresh-spec, dev-up, dev-down, start, stop, restart, status, retire
  (assumed in v1). System lane (human-driven): template-check; template-new
  skipped and version bumps later (both assumed).
- create: validate ID, scaffold app, write pin, create empty DB plus migrate
  to latest (constants ride the first migrations — assumed over a binary
  template DB), render proxy file, reload Caddy. Verb name `create` assumed.
- build: app source to mirrored `bin/` output. UI builds regenerate the Hey
  API client from `spec/` snapshots first.
- deploy: build, ensure proxy file, reload, then per type — API: backup DB
  (file copy), migrate, restart, health-check through Caddy, prune backups to
  three (assumed); UI: swap bundle, verify through Caddy. Failure restores
  the backup and aborts loudly; brief 502 window accepted.
- dev-up/dev-down: per-session dev copies (sockets, scratch DBs, `/dev/`
  routes). dev-up owns routes; e2e builds its bundle first (assumed split).
- check: direct-socket API checks plus UI bundle checks, no browser, no Caddy.
- refresh-spec: explicit copy of an API's current spec into a UI snapshot;
  never automatic.
- retire: stop, remove proxy file plus reload, archive the app dir plus its `data/` dir (assumed).
- start/stop/restart/status: pidfile supervision per deployment; status covers
  process state plus endpoint health. Pids live beside sockets.

## E2E standard

- Hermetic runs: every invocation mints a fresh session and tears it down,
  always — failed runs preserve scratch and print its location for debugging.
- Contract every template builds to: specs live in `apps/<id>/e2e/`; the verb
  injects base URLs and the artifacts dir as env vars and specs never hardcode
  addresses; exit code plus artifacts is the report.
- Runners are per template: `go test ./e2e/` with testify for APIs (HTTP flows
  through the `/dev/` route, testing prefix behavior too); Playwright Test
  with headless browser for UIs. Browser binaries provisioned at
  implementation.
- Callers: ui-dev routinely, planner as the cross-stack integration gate,
  api-dev only when proxy-path behavior is under test, human on demand.

## Spec handoff and migrations

- API truth: the DSL is the contract; `gen/` is committed and must regenerate
  with no diff (regen-cleanliness gate); OpenAPI is derived truth served at a
  stable route.
- UI snapshots: `apps/<ui>/spec/<api-id>.openapi.json`, one per consumed API,
  each UI upgrading independently. Every UI build byte-compares snapshots
  against current specs and fails on drift with the refresh command. New API
  versions never silently reach a UI.
- Migration files live app-owned under `apps/<id>/migrations/`. Migrate runs
  as an explicit harness step (not on boot), against scratch for dev and
  stable for promotion; fresh deploys create plus migrate from zero. The
  migrate version pin lives in `tools/` (assumed). SQLite driver resolved via
  a build check at implementation (must keep plain `go build` working).

## Validation plan

- `create` then `build` then `deploy` for one API plus health through Caddy;
  same triple for one UI; both green from a bare clone with documented
  prerequisites (Go, Node, Caddy).
- Mutate a template example and re-run: direct `check`, browser `e2e` through
  `/dev/`, snapshot-drift failure plus explicit refresh recovery.
- Combined demo: one project with two APIs and one UI consuming both, brought
  up and reset with one action each; kill -9 an API mid-run and confirm
  proxy 502 plus clean restart recovery.
- Exit gate: a fresh-prompt Muse session scaffolds a new API plus UI pair from
  READMEs alone and passes the same health checks as the direct path.

## Work steps

1. Template manifests, READMEs, and scaffold sources for both templates.
   Validates by direct builds (`go build`, `vite build`) since no harness
   exists yet.
2. `tools/` skeleton plus `lib.sh` (ID rules, path derivation, reload, help
   scaffolding) plus `template-check`: scaffold scratch app, build, check,
   tear down. Re-validates both templates through the harness. Validates by
   clean `--help` runs on stubs plus a shell lint pass.
3. `create`/`build`/`deploy` path for one API end to end with migrate plus
   backup/restore proven by a forced failing migration. Resolve exact version
   pins (Goa, Go, Node, React) and the SQLite driver here.
4. Same path for one UI with Hey API regen, snapshot freshness, and cache
   headers verified by response inspection.
5. `dev-up`/`dev-down`, `check`, `e2e`, `refresh-spec`, `retire`, supervisor
   verbs; combined demo; exit gate.

## Agent parallelization

Freeze first (already decided; these docs are the freeze): descriptor
schemas, ID rules, e2e env interface. Templates pack (one agent per template)
and runtime pack (`proxy/` behavior, `run/` conventions) run parallel now;
tools pack (`tools/` plus `lib.sh`) starts once templates complete;
integration pack (runners wired, demo apps, exit gate) last. Packs share no
files; each validates against the frozen contracts, never against another
pack's unfinished output.

## Risks

- Helper-path drift: the helper may only call the same scripts Muse uses;
  parity is tested, not assumed.
- Goa socket listen or driver friction discovered at implementation: both are
  flagged acceptance items in steps 2–3 with fallback to loopback TCP
  documented if sockets fail (ports would then be harness-assigned ephemeral,
  never configured).
- Scope creep into console, packaging, or second stacks: the deferred list in
  roadmap holds the line.

Port `:8080`; strip API prefixes; constant Host; UI fallback plus cache split;
default Caddy logging; `.sh` harness; `create` name; `retire` in v1;
`template-new` skipped; bumps later; `dev-up` routes-only with e2e building
bundles; empty `vars` kept; deployment dirs flat once scaffolded; app config

transports; pins plus driver plus socket verification at implementation;
compiler-plus-regen strictness only; TanStack later; constants via first
migrations; prune-to-three backups; migrate pin in `tools/`; go module path convention;
`app.env` config; `/healthz` shape; `/openapi.json` route; E2E env names; Hey
per-spec loop with committed output; atomic `bin/` promotion; `*.db` ignored;
dev bundle profile (maps on, minify off); demo composition; retire archives
data alongside; backup suffix `.bak-<timestamp>`.
